# ADR-0006：智能客服检索降级策略（词法兜底 + 可插拔向量）

- **状态**：Accepted
- **日期**：2026-11-01
- **决策范围**：V3.0 智能客服
- **相关**：ADR-0002、ADR-0005、`docs/03-ai/customer-service-智能客服.md` §4.2

## 背景（Context）

设计基线（§4.2）要求 RAG：文档/商品切片 → embedding → PgVector → topK 检索。但 2026-11-01 实测：本项目可用的所有 LLM 网关（wb2api 系列、deepother）**均不提供 embeddings 端点**。若强绑定向量检索，V3.0 交付即被外部依赖卡死。

## 决策（Decision）

1. 统一检索接口 `Retriever`（入参 query/topK/类型，出参带来源的结构化片段），两个实现：
   - `VectorRetriever`：PgVector cosine（`knowledge_chunk` / `product_chunk.embedding`），需 EmbeddingClient 可用；
   - `LexicalRetriever`：商品按 `name/subtitle` 关键词 bigram LIKE + 销量权重；知识按 `tsvector` 全文，**纯 PostgreSQL，无外部依赖**。
2. 模式由配置 `retrieval.mode = auto | lexical | vector` 控制，默认 `auto`：配置了 embedding 且存在已向量化数据 → 向量优先，异常自动回落词法；未配置 → 词法。
3. 数据管道：知识文档保存/发布 → 待向量化 → 后台「重建索引」触发异步切片+向量化（`EmbeddingClient` 可用时）；商品切片由 `@Scheduled` 增量 + 管理端全量重建，数据源为 `commerce-api` 快照接口。
4. 向量维度在迁移中按当时选定模型固定（默认 1024）；更换 embedding 模型 = 新增迁移重建列 + 全量重建（文档写明操作步骤）。

## 后果（Consequences）

- 正面：开箱可用（词法模式即可完整演示 A1/A3）；任意 OpenAI 兼容 embedding 服务两步接入（填配置 → 后台重建）；检索失败不影响对话主链路。
- 负面：词法模式对同义/模糊描述召回弱（如「跑鞋」匹配不到「运动鞋」），依赖运营维护副标题/FAQ 关键词。
- 风险：`auto` 模式的静默回落可能掩盖向量异常 → 回落时记录 WARN 审计并在管理端向量化状态页可见。
