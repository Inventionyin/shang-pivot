# ADR-0005：LLM 网关接入与两阶段编排

- **状态**：Accepted
- **日期**：2026-11-01
- **决策范围**：V3.0 智能客服
- **相关**：ADR-0002（技术栈）、`docs/03-ai/customer-service-智能客服.md`、`docs/01-requirements/PRD-V3.0-智能客服.md`

## 背景（Context）

V3.0 需要接入大模型。约束与实测事实（2026-11-01）：

1. 用户指定使用 zcode 配置的 wb2api 网关（OpenAI 兼容 chat-completions）`cn:deepseek-v4.1-flash`。实测主站 `wb2api.billnb666.site` 当时被上游限制（错误码 11140「账号异常」，申诉周期 1~3 个工作日）；镜像 `wb2api.yingyue.cloud` 同模型实测可用（含 SSE 流式）。
2. 该网关系列模型均为**思考型**：先输出 `reasoning_content`（思考增量）再输出正文，UI 与后端必须显式处理。
3. 网关为 web-to-API 转换层，对原生 function calling（`tools`/`tool_calls`）支持不可靠。
4. 所有已配网关均无 `/v1/embeddings` 端点，RAG 向量化无法依赖对话网关。

## 决策（Decision）

1. **网关接入层**：自建 `LlmClient`（Spring `RestClient` + SSE 流式解析），协议 OpenAI chat-completions 兼容；`base-url / api-key / model / temperature / system-prompt` 走 `.env` 默认 + `identity.system_config`（LLM 分组）覆盖，管理端「AI 配置」可改并连通性测试。默认指向 `https://wb2api.yingyue.cloud/v1` + `cn:deepseek-v4.1-flash`。
2. **两阶段提示词编排**（不依赖原生 tool_calls）：
   - 阶段一（意图与参数）：轻量提示词让模型输出 JSON `{intent, slots}`（售前/订单/物流/售后/知识/闲聊 + 关键词、类目、订单号等槽位）；
   - 阶段二（执行与生成）：后端按意图执行工具（走 `commerce-api`/`identity-api`）与检索，将结构化结果拼入上下文，再让模型流式生成回答。
3. **思考流处理**：SSE 解析区分 `reasoning_content` 与 `content`，分别以 `reasoning` / `delta` 事件下发前端；思考阶段设 10s 首包超时与总量上限，超限截断进入正文阶段。
4. **Embedding 可插拔**：`EmbeddingClient`（OpenAI 兼容 `/v1/embeddings`）独立配置；未配置时检索降级（见 ADR-0006）。

## 后果（Consequences）

- 正面：网关可随时经配置切换（.env / 管理端），不绑定单一供应商；编排不依赖 tool_calls，兼容任意 OpenAI 兼容网关；思考流透明可展示。
- 负面：两阶段比原生 function calling 多一次模型往返（延迟 +1~3s）；意图槽位 JSON 需容错解析（失败回退售前意图）。
- 风险：web2api 类网关稳定性弱（本日实测封禁事件）→ 必须保留降级链（ADR-0006）；API Key 属密文配置（`is_secret`），日志禁止打印。
