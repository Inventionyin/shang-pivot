# V3.0 接口设计 — 智能客服

> 对齐 `docs/03-ai/customer-service-智能客服.md` §6 与 ADR-0005/0006。统一响应 `{code,msg,data,traceId}`；鉴权：C 端走 C-JWT（`/api/**` 规则），管理端走 admin-JWT + RBAC。命名空间：C 端 `/chat/**`（设计文档口径，Spring 映射到 `/api/chat/**` 由网关层一致性说明见 §5）。

## 1. C 端接口

| 方法 | 路径 | 说明 | 入参 → 出参要点 |
|---|---|---|---|
| POST | `/api/chat/sessions` | 创建/取进行中会话 | → `sessionId, status, greeting, quickQuestions[]` |
| GET | `/api/chat/sessions` | 我的会话列表 | `page,size` → 分页（含最后一条消息摘要） |
| GET | `/api/chat/sessions/{id}/messages` | 历史消息回放 | `beforeId?` → 消息数组（含卡片） |
| POST | `/api/chat/sessions/{id}/messages` | 发消息（**SSE 流式**） | `{content}` → 事件流 |
| POST | `/api/chat/messages/{id}/feedback` | 对单条 AI 回答点赞/点踩 | `{rating:UP/DOWN, reason?, comment?}` → `{messageId,rating}` |
| POST | `/api/chat/sessions/{id}/escalate` | 转人工 / 撤回 | `{cancel?:boolean}` → 会话状态 |
| GET | `/api/chat/quick-questions` | 推荐问 | → `string[]` |

**SSE 事件协议**（`text/event-stream`）：

```
event: reasoning   data: {"delta":"..."}        // 思考增量（可折叠展示）
event: delta       data: {"delta":"..."}        // 正文增量
event: cards       data: {"items":[ProductCard]} // 商品卡片（真实数据，后端构造）
event: done        data: {"messageId":...,"sessionStatus":"AI_ONGOING","degraded":false}
event: error       data: {"code":...,"msg":"..."}
```

规则：`cards` 至多一次、在 `done` 前；`degraded=true` 表示本次为降级应答；心跳注释行 `: ping` 每 15s；客户端断开即终止上游并异步落库已生成内容。

## 5. 路径说明

## 6. V3.1 Agent 运行时增量（2026-11-07）

### 6.1 C 端确认接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/chat/sessions/{id}/actions/{actionId}/confirm` | 确认执行写操作；重复确认幂等返回 |
| POST | `/api/chat/sessions/{id}/actions/{actionId}/cancel` | 取消待确认动作；仅 PENDING 可取消 |

### 6.2 SSE 事件增量

原有 `reasoning / delta / cards / done / error` 不变，新增：

| 事件 | data | 说明 |
|---|---|---|
| `state` | `{state, label}` | `ROUTING / TOOL_CALLING / ANSWERING`，前端显示进度 |
| `action` | `{actionId, tool, summary, args, expiresAt}` | 写操作待确认卡片；用户确认/取消后走 6.1 |
| `done` 增量 | `runId, agent, intent, tools, tokens` | 运行轨迹与工具名，供前端/评测使用 |

### 6.3 管理端轨迹接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/customer-service/agent-runs?status=&agent=&intent=&page=&size=` | 运行轨迹分页（权限 `cs:agent:view`） |
| GET | `/admin/customer-service/agent-runs/{runId}` | 详情：run + steps + llmCalls + toolCalls + retrievals |
| GET | `/admin/customer-service/stats?range=today|week` | 新增 `agentRuns/agentSuccessRate/p95LatencyMs/toolErrorRate/handoffRate/retrievalMissRate` |

## 7. V3.7 多轮澄清与答案质量增量（2026-11-11）

### 7.1 话轮承接

当上一轮助手提问包含“请回复序号 / 您指的是哪一款 / 有多个规格 / 【商品N】”时，下一轮裸序号（`1`、`第一个`、`选2`）或确认词（`确认`、`好的`、`行`、`嗯`）由 `ConversationFollowUpService` 确定性承接，不再调用 LLM 重新分类：

- 商品序号 → `ADDCART` + 对应商品名；
- 规格序号 → `ADDCART` + 商品名，由 `pickSku` 选择 SKU；
- 多候选下只说“确认” → 仍走歧义反问，不猜。

### 7.2 答案反馈

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/chat/messages/{id}/feedback` | 对单条助手回答点赞/点踩；同一用户对同一消息重复提交覆盖 |
| GET | `/admin/customer-service/quality?days=14` | 答案质量看板：总数、点赞/点踩率、点踩原因分布 |
| GET | `/admin/customer-service/quality/trend?days=14` | 按天点赞/点踩/点踩率 |
| GET | `/admin/customer-service/quality/negative-feedback?limit=20` | 最近点踩明细（含回答预览、runId） |

反馈写入 `customerservice.message_feedback`（V33）；`reason` 取值：`答非所问 / 商品不对 / 没有执行 / 信息不准确 / 态度不好 / 其他`。差评与“澄清后未承接”会由 `scripts/eval/mine_failure_candidates.py` 挖成候选用例，人工复核后进入 `conversation-repair` 套件。
