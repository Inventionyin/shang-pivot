# V3.0 接口设计 — 智能客服

> 对齐 `docs/03-ai/customer-service-智能客服.md` §6 与 ADR-0005/0006。统一响应 `{code,msg,data,traceId}`；鉴权：C 端走 C-JWT（`/api/**` 规则），管理端走 admin-JWT + RBAC。命名空间：C 端 `/chat/**`（设计文档口径，Spring 映射到 `/api/chat/**` 由网关层一致性说明见 §5）。

## 1. C 端接口

| 方法 | 路径 | 说明 | 入参 → 出参要点 |
|---|---|---|---|
| POST | `/api/chat/sessions` | 创建/取进行中会话 | → `sessionId, status, greeting, quickQuestions[]` |
| GET | `/api/chat/sessions` | 我的会话列表 | `page,size` → 分页（含最后一条消息摘要） |
| GET | `/api/chat/sessions/{id}/messages` | 历史消息回放 | `beforeId?` → 消息数组（含卡片） |
| POST | `/api/chat/sessions/{id}/messages` | 发消息（**SSE 流式**） | `{content}` → 事件流 |
| POST | `/api/chat/sessions/{id}/escalate` | 转人工 / 撤回 | `{cancel?:boolean}` → 会话状态 |
| GET | `/api/chat/quick-questions` | 推荐问 | → `string[]` |

**SSE 事件协议**（`text/event-stream`）：

```
event: reasoning   data: {"delta":"..."}        // 思考增量（可折叠展示）
event: delta       data: {"delta":"..."}        // 正文增量
event: cards       data: {"items":[ProductCard]} // 商品卡片（真实数据，后端构造）
event: done        data: {"messageId":...,"sessionStatus":"AI_ONGOING","degraded":false}
event: error       data: {"code":...,"msg":"..."}
```

规则：`cards` 至多一次、在 `done` 前；`degraded=true` 表示本次为降级应答；心跳注释行 `: ping` 每 15s；客户端断开即终止上游并异步落库已生成内容。

## 2. 管理端接口（`/admin/customer-service/**`，权限码见括号）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/sessions?status=&page=&size=` | 会话列表（`cs:session:list`） |
| GET | `/sessions/{id}` | 会话详情 + 消息 |
| POST | `/sessions/{id}/claim` | 接入（`cs:session:handle`；排队中才可，竞态返回错误） |
| POST | `/sessions/{id}/messages` | 坐席发消息（同步返回） |
| POST | `/sessions/{id}/transfer` | 转接 `{targetSeatId}` |
| POST | `/sessions/{id}/end` | 结束 `{summary?}` |
| POST | `/sessions/{id}/back-to-ai` | 退回智能客服 |
| GET/POST/PUT/DELETE | `/tickets`(`/id`) | 工单 CRUD + `POST /tickets/{id}/transition`（`cs:ticket:*`） |
| GET/POST/PUT/DELETE | `/knowledge-docs`(`/id`) | 知识库（`cs:kb:*`） |
| POST | `/knowledge-docs/rebuild` | 重建向量索引 `{docId?, full?}` |
| GET/POST/PUT/DELETE | `/quick-replies`(`/id`) | 快捷回复（`cs:quick:*`） |
| GET/PUT | `/seats`(`/id`) | 坐席状态与并发（`cs:seat:*`） |
| GET | `/stats?range=today|week` | 看板聚合 |
| GET/PUT | `/ai-config` | AI 配置（LLM 分组 system_config）；`POST /ai-config/test` 连通性测试 |

## 3. 跨上下文进程内接口（扩展 `shang-commerce-api`）

```java
ProductQueryApi {
  List<ProductCardDTO> search(String keyword, int limit);       // 名称/副标题 LIKE，销量排序
  List<ProductCardDTO> getBySpuIds(Collection<Long> spuIds);    // 仅在售
  List<ProductSnapshotDTO> snapshotPage(Long lastSpuId, int limit); // 索引快照（增量游标）
}
OrderQueryApi += {
  PageResult<OrderBriefDTO> pageByCustomer(Long customerId, int page, int size);
  OrderTraceDTO getTrace(Long customerId, String orderNo);      // 订单 + 发货/轨迹（沙箱）
}
```

实现落 `shang-commerce`（`ProductQueryApiImpl`、`OrderQueryApiImpl` 扩展），复用 `CatalogReadService.toCard` 口径。红线：`shang-customerservice` 不 import commerce 实现类。

## 4. 领域事件

复用既有 RabbitMQ 惯例（参照 `commerce.order.event`）：`customerservice.session.event`（routing：`session.escalated` / `session.claimed` / `session.ended`）供后续扩展；V3.0 内仅坐席侧轮询消费状态，不强制引入。

## 5. 路径说明

设计文档写 `/chat/**`，实现统一挂在 `/api/chat/**`（与既有 `/api/**` C 端命名空间、JWT 规则一致）；管理端 `/admin/customer-service/**`。文档与代码不一致处以本文件为准。
